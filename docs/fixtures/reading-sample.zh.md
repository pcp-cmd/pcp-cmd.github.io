# 把一次尝试记录清楚

日期待提供 · 长文 · 排版样文

用途：合成中文长文，仅用于本地阅读排版检查。不是 Aleksi 的真实文章，不代表研究进展或真实项目成果，不作为公开内容自动发布。

## 先说明问题

开始一次尝试之前，先把问题写清楚，往往比急着选择工具更有帮助。想要改善的可能是一段难懂的文字，也可能是一项重复操作。问题越具体，后来越容易判断这次尝试究竟改变了什么。工具给出的结果可以先保存，但对结果的解释需要有依据。

记录不必从头到尾复述全部操作。读者通常更需要知道任务的背景、受到的限制，以及最初为什么选择这条路径。如果某个条件后来发生变化，也应当在相应位置说明。这样，读者看到的就不只是一个结果，还能理解这个结果成立的范围。

## 把过程与判断分开

一次尝试没有达到预期，并不意味着所有过程都没有用。也许某一步暴露了材料缺口，也许一个看似合理的设定没有得到支持。把这些情况分开记录，可以避免把局部的问题扩大成对整个方法的判断。暂时不能确定的部分，可以明确写成待核实。

与 AI 协作时，回答的流畅程度不能替代证据。模型提出的解释可以成为下一步检查的对象；经过检查的结论，才适合用来支持后续判断。如果记录只留下最后一段漂亮的总结，读者就很难分清哪些来自观察，哪些仍然只是一个可能的解释。

有效的记录，应当让后来的人知道当时为什么这样做，以及哪些判断仍然需要核对。

## 让旧记录能够再次被使用

当另一个问题出现时，一条旧记录是否有用，取决于两次问题之间有什么具体联系。相似的名字并不保证相同的方法适用。重新使用之前，需要核对原来的条件，并说明这次保留了什么、调整了什么。如果条件不满足，旧记录也可以帮助排除一条不适合的路径。

因此，保存材料时，可以同时留下问题、处理方式和适用边界。原始文件的位置、关键判断的依据，以及尚未解决的疑问，都可以成为以后检索的线索。这些线索不需要占据正文的每一段，但应当能在需要时找到。记录的价值，可以来自一次成功，也可以来自一次被认真说明的失败。

## 给阅读留下空间

长文需要连续阅读，也需要让读者在停顿后找到刚才的位置。标题可以提示段落的主题，但不必给每句话都加一个标题。段落之间保留适当距离，可以帮助区分论点；同一个论点内部的句子则应保持连贯。文字密度与留白需要一起观察，不能只看某一行是否整齐。

手机上的页面更窄，同样一段文字会占据更多行。此时应当允许标题和正文自然换行，而不是把整页缩小。遇到很长的链接、表格或代码时，可以在对应内容区域处理宽度，让普通段落继续保持原来的阅读大小。返回入口也应当清楚，使读者在读完或中途离开时都知道可以去哪里。
